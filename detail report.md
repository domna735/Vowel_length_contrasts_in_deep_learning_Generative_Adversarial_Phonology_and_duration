**Workspace**: `C:\GAN_2025`

**Project focus**: Generate Vietnamese vowel audio conditioned on length (short vs long) using a conditional WGAN-GP trained on fixed-size log-mel spectrograms; evaluate phonetic realism via VOT and intensity metrics.

---

## Abstract

This project develops an end-to-end, reproducible research pipeline for training and evaluating a conditional generative adversarial network (ciwGAN) that synthesizes Vietnamese vowel audio with controllable duration class (short vs long). Audio is modeled as fixed-size log-mel spectrogram patches (128 mel bins × 128 time steps) generated by a conditional generator and judged by a discriminator (critic) trained with WGAN-GP objectives and an auxiliary duration-class head. Generated spectrograms are inverted back to waveforms using Griffin–Lim style mel inversion.

The evaluation emphasizes linguistically meaningful, measurable phonetic properties rather than only perceptual listening. Two metrics are used: (1) Voice Onset Time (VOT), computed as the delay between an energy burst and subsequent voicing onset, and (2) intensity (RMS dB), capturing amplitude dynamics. Across training stages, the system demonstrates clear progress: the 1-epoch pilot fails to preserve VOT, the 30-epoch baseline substantially reduces VOT error, and the 100-epoch model perfectly matches the *generated* long-vowel VOT median to the *available* real reference median (0 ms median error) while short-vowel median VOT remains offset (7.5 ms median error). Intensity is strongly affected by Griffin–Lim inversion; a normalization step improves intensity similarity but a residual 15–18 dB offset persists.

The project’s main contributions are (a) a working conditional GAN training + generation stack, (b) a metrics/visualization/packaging workflow suitable for a PhD writing sample, and (c) an evidence-driven analysis of remaining gaps (short-vowel VOT mismatch, amplitude realism limits, dependence on external datasets).

## 1. Introduction and Background

### 1.1 Research motivation

Human listeners are sensitive to fine-grained timing cues in speech. For stop-consonant + vowel sequences (CV), **Voice Onset Time (VOT)** measures the time between the stop release burst and the onset of periodic voicing. In many languages, these delays are short (often under ~20 ms) but carry meaningful phonetic structure.

Separately, many languages also encode **vowel length contrasts** (short vs long). Depending on the language, the contrast may be mostly temporal (duration) or coupled with other properties (e.g., spectral/quality shifts, tonal interactions).

The central question for this project is:

> Can a conditional GAN learn to generate vowel sounds with controllable duration class while preserving measurable phonetic structure (especially sub-20 ms timing cues like VOT) without explicit supervision on those timing cues?

### 1.2 Practical goal and deliverables

The project targets two outcomes:

1. **A working generative pipeline**: train a conditional GAN on Vietnamese vowel recordings and generate short/long vowel samples.
2. **A research-style evaluation package**: compute objective metrics, compare distributions (real vs generated), generate plots and summary tables, and bundle everything into a deliverables folder suitable for presentation or a PhD application.

## 2. Literature Review (brief)

This project builds on several widely used ideas in modern generative audio and GAN training.

### 2.1 GANs for audio and spectrogram-based synthesis

- **WaveGAN / SpecGAN** introduced adversarial synthesis for audio, including spectrogram-based generation pipelines.
- Spectrogram generation is attractive because it reduces waveform complexity and allows 2D convolutional architectures.

### 2.2 Stable GAN training with Wasserstein objectives

- **WGAN-GP** (Wasserstein GAN with gradient penalty) stabilizes training by optimizing a critic with an approximate Lipschitz constraint.
- This project uses a WGAN-GP style critic loss plus an auxiliary classifier head to encourage correct conditioning.

### 2.3 Conditional generation and auxiliary objectives

- Conditional GANs inject side information (here: `class_id ∈ {0,1}` for short/long) into the generator.
- InfoGAN-style categorical heads (or auxiliary classification losses) can improve disentanglement of the conditioning variable.

### 2.4 Spectrogram inversion and neural vocoders

- Griffin–Lim style algorithms (or mel inversion variants) reconstruct audio from magnitude-like representations but often degrade phase and amplitude realism.
- Modern **neural vocoders** (e.g., HiFi-GAN) typically produce much more natural amplitude/phase dynamics.

## 3. Methodology

### 3.1 Repository organization

Core work is in:

- `tools/` — training, generation, evaluation scripts
- `runs/` — run artifacts (checkpoints, TensorBoard logs, generated audio, metric CSVs, comparisons, deliverables)
- `docs/` — design and narrative documentation

Large datasets are intentionally **not** required to be committed to Git (see `.gitignore`). The code expects a local dataset path at runtime.

### 3.2 Data and labeling

**Data type**: speech recordings (e.g., Vietnamese vowel tokens) stored as `mp3`/`wav` audio files.

**Labeling strategy** (implemented in `tools/train_ciwgan.py`):

- Duration class is inferred from directory names:
  - any parent directory containing `long` → class `1`
  - any parent directory containing `short` → class `0`
- Fallback: if neither exists, the filename is scanned for a long-vowel marker `ː`.

This allows training on datasets organized like:

```text
<data-root>/
  .../long vowels-#XX/*.mp3
  .../short vowels-#XX/*.mp3
```

### 3.3 Feature representation: fixed-size log-mel patches

In `tools/train_ciwgan.py`, each audio file is mapped to a log-mel spectrogram patch:

- Resample to `sr = 16000`
- Mel spectrogram:
  - `n_mels = 128`
  - `n_fft = 1024`
  - `hop_length = 256`
- Convert power → dB (`librosa.power_to_db`)
- Normalize dB range `[-80, 0]` → `[-1, 1]`
- Time dimension fixed to `time_steps = 128`:
  - if shorter: pad with `-1`
  - if longer: random crop to 128 frames

Final model input shape: `(128, 128, 1)`.

**Why fixed-size?**

- Makes training stable and simple with 2D conv networks.
- Enables efficient batching and avoids variable-length masking in v0.1.
- Trades off exact duration modeling for a consistent representation.

### 3.4 Model architecture (ciwGAN v0.1)

Defined in `tools/ciwgan_model.py`.

**Conditioning**:

- Latent `z ~ N(0, I)` with `z_dim = 64`
- Duration class `c ∈ {0,1}` converted to one-hot
- Generator input is concatenated: `[z, onehot(c)]`

**Generator** (high-level):

- Dense projection → reshape to a small spatial map `(8, 8, channels)`
- Upsampling blocks (nearest-neighbor upsample + `Conv2D` + optional BatchNorm + LeakyReLU)
- Final `Conv2D(..., activation='tanh')` to output `[-1,1]` log-mel

**Discriminator / Critic**:

- 2D conv downsampling stack with LeakyReLU
- Flatten → dense layer
- Two heads:
  - critic score (scalar)
  - class logits (2-way)

### 3.5 Training objective and procedure

Implemented in `tools/train_ciwgan.py`.

**Core losses**:

- WGAN critic loss: $\mathbb{E}[D(x_{fake})] - \mathbb{E}[D(x_{real})]$
- Gradient penalty (GP) with weight `λ = 10`
- Auxiliary classification loss (real examples): sparse cross-entropy of duration class
- Generator loss:
  - adversarial term: $-\mathbb{E}[D(x_{fake})]$
  - plus auxiliary classification loss on fake samples (encourage correct conditioning)

**Training schedule**:

- `critic_steps = 5` discriminator updates per generator update
- Adam optimizer with `lr = 2e-4`, `β1=0.5`, `β2=0.9`

**Logging and outputs**:

- TensorBoard scalars (loss components)
- Checkpoints saved under `runs/checkpoints/ciwgan_<timestamp>/`
- Periodic sample generation under `runs/gen/ciwgan_<timestamp>/`

### 3.6 Generation and waveform reconstruction

Implemented in `tools/generate_ciwgan.py`.

**Generator restore**:

- Restore `G` from a checkpoint prefix like `runs/checkpoints/.../ckpt-100` (or a directory containing checkpoints)

**Spectrogram inversion**:

- Convert `[-1,1]` log-mel back to dB `[-80,0]`
- Convert dB to power
- `librosa.feature.inverse.mel_to_audio(..., n_iter=32)`

This inversion is convenient and fully local, but it is also a major source of amplitude/phase artifacts (see Limitations).

### 3.7 Evaluation metrics

All evaluation scripts live in `tools/` and output CSVs into `runs/`.

#### 3.7.1 VOT (Voice Onset Time)

- Script: `tools/compute_vot.py`
- Outputs: CSV like `runs/vot_100ep_long_250.csv`
- Fields: `rel_path, vot_ms, confidence, burst_frame, voice_frame`

VOT computation uses a heuristic approach:

1. Identify a burst using energy thresholding.
2. Identify voicing onset using periodicity / pitch cues.
3. Compute: `VOT = voicing_time - burst_time`.

#### 3.7.2 Intensity (RMS dB)

- Script: `tools/compute_intensity.py`
- Outputs: `runs/intensity_100ep_short_250.csv`, etc.
- Fields: `mean_db, max_db, median_db, peak_to_mean`

#### 3.7.3 Distribution comparisons and plots

- `tools/compare_vot_distributions.py` and `tools/compare_intensity_distributions.py` compute summary statistics and absolute differences.
- `tools/plot_metrics.py` generates overlay histograms + boxplots.

### 3.8 Packaging for sharing

- Script: `tools/package_deliverables.py`
- Output folder: `runs/deliverables/vietnamese_100ep/`
- Contents include:
  - key reports (`COMPLETE_EVALUATION_REPORT.md`, `SIMILARITY_RESULTS_SUMMARY.md`)
  - metric CSVs (generated + comparisons)
  - summary tables (e.g., `OVERALL_RESULTS_SUMMARY.csv`)
  - representative audio samples

### 4.3 VOT analysis

#### 4.3.1 What the numbers mean

- The **pilot model** clearly fails: VOT medians in the hundreds of ms are inconsistent with typical CV timing.
- By **30 epochs**, generated VOT medians become plausible (5–11 ms range).
- By **100 epochs**, long-vowel median matches the stored real median exactly (7.5 ms), but short-vowel median remains higher (15 ms).

#### 4.3.2 Important caveat: real VOT reference stored in-repo

The stored `runs/vot_real.csv` currently contains **only one** real VOT entry. As a result:

- The real median (7.5 ms) is plausible, but the real distribution statistics (mean/std) cannot be trusted from the CSV alone.
- Some comparison CSVs (e.g., `runs/compare/vot_100ep_long_250_vs_real.csv`) report `real_n = 1`.

This limitation does **not** invalidate the generated distributions (250 samples each), but it limits how confidently we can quantify real-vs-generated distribution overlap for VOT within this code-only workspace.

**Recommended fix**: regenerate `runs/vot_real.csv` from the full real dataset on the machine that has the audio, then re-run `compare_vot_distributions.py` and `plot_metrics.py`.

#### 4.3.3 Why short-vowel VOT is “like that” (open question)

The 100-epoch short-vowel VOT median is 15 ms vs the stored real median 7.5 ms (a +7.5 ms shift). Candidate explanations consistent with the project evidence:

1. **Conditioning leakage / weak control**: the class signal may not fully control the specific timing cue used by the VOT heuristic.
2. **Dataset imbalance**: earlier dataset validation noted a strong long:short imbalance (reported approximately 3:1 in logs). In imbalanced settings, the generator may learn long-class timing more reliably.
3. **Measurement sensitivity**: VOT detection is heuristic and may behave differently on synthetic audio (e.g., burst detection triggered by Griffin–Lim artifacts).
4. **Training dynamics**: improvements in one class can occur at the expense of the other due to adversarial training instabilities.

#### 4.3.4 Follow-up analysis: “duration-quality coupling” hypothesis

An early narrative interpretation proposed that Vietnamese short vs long vowels may differ not only by duration but also by vowel quality. A later follow-up spectral analysis script (`tools/analyze_vowel_qualities_simple.py`) tested for differences using simple spectral proxies over `processed_data/*.npy` files and found:

- No clear evidence of strong centroid/formant-proxy shifts between the inferred short and long groups.
- Significant differences in spectral spread and rolloff.

This is **not** a definitive phonetic conclusion (the proxy is coarse and the dataset mix/label inference may be imperfect), but it provides a concrete direction: if short/long quality coupling is a real factor, it should be tested with more targeted analyses (token-controlled formant tracking, per-token grouping, or explicit vowel identity conditioning).

### 4.4 Intensity analysis

Intensity comparisons are well-supported in the stored CSVs. Example (normalized, 100-epoch):

- Real intensity summary is computed over `real_n = 683` samples (from `runs/intensity_real.csv`).
- After normalization:
  - Long generated mean: -53.08 dB vs real -37.70 dB (≈ 15.39 dB quieter)
  - Short generated mean: -55.96 dB vs real -37.70 dB (≈ 18.27 dB quieter)

**Interpretation**:

- The large raw offset (~42–44 dB in the summary table) is consistent with Griffin–Lim mel inversion producing substantially quieter outputs.
- Normalization improves the mismatch but leaves a persistent 15–18 dB gap.
- Generated intensity variance is smaller than real, suggesting reduced dynamic range.

### 4.5 “Could cues be found in the latent space?”

Yes—this is a strong next step. The project already includes a starting point (`tools/explore_latent_space.py`) intended to:

- Interpolate between latent vectors `z1 → z2`
- Generate samples at each step for both classes
- Compute VOT along the path

If VOT changes smoothly with `z`, duration cues are entangled in the latent space. If VOT is stable within a class across interpolation, the class label dominates duration control.

As of this report, the script is a scaffold and needs a small integration pass (loading the generator consistently with current checkpoints and reusing existing inversion + metric utilities).

## 6. Discussion and Limitations

### 6.1 Data availability and reproducibility

The repository is intentionally kept lightweight; large datasets and many run artifacts are excluded from Git. This improves sharing but means:

- Users must supply `--data-root` paths locally.
- Real-reference CSVs (especially VOT) may be incomplete inside the repo unless regenerated.

### 6.2 Fixed-size spectrogram patches limit duration modeling

The model generates a fixed `(128 × 128)` time-frequency patch. This is a pragmatic design for stability but does not model variable-length waveforms directly.

### 6.3 Griffin–Lim inversion is a bottleneck

Intensity and perceptual realism are constrained by spectrogram inversion. The persistent intensity gap (15–18 dB after normalization) is consistent with reconstruction limitations. Integrating a neural vocoder is the highest-value technical improvement.

### 6.4 VOT measurement is heuristic

VOT estimation can be sensitive to:

- burst threshold
- synthetic transients
- pitch tracking behavior on noisy signals

To strengthen claims, future work should include manual inspections, robustness checks, and/or Praat-based alignment for a subset.

### 6.5 Short-vowel VOT remains unexplained

The 100-epoch short-vowel median VOT shift is the main unresolved phonetic issue in the current results. It is a strong candidate for latent-space probing and data-balancing experiments.

## 8. Lessons Learned from Development

1. **Reproducibility requires explicit interpreter paths on Windows**: venv activation can still resolve to the WindowsApps Python shim; using `.venv_*\Scripts\python.exe` avoids ambiguous PATH resolution.
2. **Keep the repo small early**: datasets and generated audio must be excluded by default; selectively package results for sharing.
3. **Adversarial training needs stage-by-stage checkpoints**: the pilot model can be dramatically wrong while later epochs become plausible; intermediate baselines matter.
4. **Metrics must be stored with sufficient real references**: for distribution comparisons, real CSVs must include enough samples to estimate mean/std reliably.
5. **Waveform inversion matters**: many “audio quality” problems in spectrogram GANs are dominated by the inversion method, not the generator itself.

## 9. Conclusion and Next Steps

### 9.1 Conclusion

This project successfully delivers a complete ciwGAN research pipeline: training, checkpointing, sample generation, objective metric computation (VOT and intensity), distribution comparison, plotting, and packaging into a shareable deliverables artifact. The results show strong learning progress across training stages, with a notable success in matching the long-vowel VOT median at 100 epochs and a clear remaining gap for short-vowel VOT and intensity realism.

### 9.2 Next steps (recommended)

1. **Regenerate real VOT reference at scale**: recompute `runs/vot_real.csv` from the full real dataset and re-run comparisons.
2. **Balance training data**: address long/short imbalance via sampling or weighting and evaluate whether short-vowel VOT improves.
3. **Latent-space probing**: complete and run `tools/explore_latent_space.py` to test where duration cues live (class vs latent).
4. **Replace Griffin–Lim with a vocoder**: integrate HiFi-GAN (or similar) to reduce intensity offsets and improve perceptual quality.
5. **Token-controlled analysis**: compute VOT by vowel token and run per-token comparisons to locate which short vowels drive the 15 ms median.
